## Amaç
Açık ve ilgisiz bir sözleşmenin yeni kullanıcı işini durdurmasını engelle. Yeni iş önce açık sözleşmelerin `owns` kümeleriyle eşleştirilsin; uygun sözleşme yoksa yeni sözleşme/ajan rotası başlatılsın. Eski açık sözleşme yalnızca kendi işi için sürsün.

## Kabul kriteri
- Relay kuralı, yeni kullanıcı işinin mevcut açık sözleşmelerden bağımsız öncelikli olduğunu açıkça uygular.
- Açık sözleşme yeni işin dosyalarını sahiplenmiyorsa builder/ui-builder `blocked` olmaz ve yeni uygun sözleşme açılır veya açıkça yeni sözleşme gerektiğini bildirir.
- Aynı dosya iki aktif sözleşmeye verilmeye devam etmez; sahiplik çakışması engellenir.
- UI Support işi açık T9 mesaj dili sözleşmesi varken T5 veya yeni UI sözleşmesine yönlenir; T9 UI işini kilitlemez.
- Ajan mesajı kısa, net ve saygılıdır; ilgisiz sözleşme nedeniyle kullanıcıdan kapsamı tekrar istemez.
- Karmaşık regresyon testleri eklenir: açık T9 + yeni Support UI isteği, açık sözleşme + ilgisiz dosya, uygun owns eşleşmesi, iki paralel ajan ve çakışan sahiplik.
- npm test, ilgili node --check ve git diff --check geçer.
- Kod yorumu eklenmez.

## Bağlam
SKILL.md §1.1 yeni kullanıcı işinin öncelikli olduğunu söyler, ancak ajan davranışı bunu sahiplik eşleştirmesiyle zorlamıyor. relay-watch.js açık sözleşme varlığını genel olarak raporluyor. test/run.js geçici relay alanları kuruyor. T9 mesaj dili işidir; T5 Support UI işidir.
